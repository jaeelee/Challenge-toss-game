## 2. 제품 개요

Liquid Blocks는 병에 섞인 여러 색상의 액체를 같은 색끼리 분류하는 워터 소트 퍼즐이다. 사용자는 퍼즐 크기와 색상 공개 난이도를 선택하고, 병을 차례로 눌러 액체를 옮긴다. 진행 상태는 기기에 저장되며 나중에 이어서 플레이할 수 있다.

현재 구현은 색상을 무작위로 배치하므로 일부 퍼즐의 풀이 가능성을 보장하지 못한다. 또한 A* 형태의 솔버 코드가 존재하지만 퍼즐 생성이나 플레이 흐름에 연결되어 있지 않고, 가변 병 높이와 실제 이동 규칙을 완전히 반영하지 않는다. 1차 출시에서는 퍼즐 생성과 풀이 규칙을 단일화하고, 현재 공개된 색상 정보의 범위 안에서 다음 수 힌트를 제공한다.

## 3. 목표와 성공 기준

### 3.1 목표

- 생성되는 모든 퍼즐에 유효한 정방향 풀이 경로를 보장한다.
- 사용자가 새 게임, 이동, 완료, 저장, 이어하기를 오류 없이 수행할 수 있게 한다.
- 일부 색상이 숨겨진 상태에서는 공개 정보만 사용하고, 모든 액체 색상이 공개된 상태에서는 A*를 사용해 다음 한 수 힌트를 제공한다.
- 병 높이와 색상 수가 달라도 생성기, 플레이 규칙, 완료 판정과 솔버가 동일한 규칙을 사용하게 한다.
- 핵심 게임 로직을 자동 테스트로 검증하고 정적 검사에 통과시킨다.

### 3.2 출시 성공 기준

- 지원하는 모든 설정에서 생성된 퍼즐의 기록 경로를 재생하면 완료 상태에 도달한다.
- 생성과 힌트 계산이 메인 UI 스레드를 장시간 차단하지 않는다.
- 저장한 게임을 복원했을 때 퍼즐, 설정과 공개 상태가 일치한다.
- 핵심 게임 규칙 테스트와 프로젝트 품질 명령이 모두 통과한다.

## 4. 대상 사용자와 핵심 흐름

### 4.1 대상 사용자

- 짧은 시간 동안 모바일에서 퍼즐을 즐기려는 사용자
- 일반 워터 소트보다 색상 가림 규칙이 있는 퍼즐을 원하는 사용자
- 막혔을 때 정답 전체가 아닌 최소한의 도움을 받고 싶은 사용자

### 4.2 핵심 사용자 흐름

1. 홈에서 난이도, 병 높이와 색상 수를 선택한다.
2. 새 게임을 시작하면 풀이 가능한 퍼즐이 생성되고 즉시 저장된다.
3. 출발 병과 도착 병을 순서대로 눌러 액체를 이동한다.
4. 유효한 이동이면 상태와 공개 정보가 갱신·저장되고, 잘못된 이동이면 상태를 변경하지 않는다.
5. 힌트를 요청하면 현재 공개 상태에 따라 공개 정보 기반 추천 또는 A*가 계산한 다음 이동 한 수를 확인할 수 있다.
6. 모든 색상을 완성하면 완료 모달이 표시되고 저장된 진행 상태가 삭제된다.
7. 완료 전 홈으로 돌아온 사용자는 저장된 게임을 이어서 플레이할 수 있다.

## 5. 기능 요구사항

### 5.1 게임 설정

- `FR-SET-01`: 난이도는 `easy`, `medium`, `hard` 중 하나여야 한다.
- `FR-SET-02`: 병 높이는 현재 UI 범위인 4~10을 지원한다.
- `FR-SET-03`: 색상 수는 현재 UI 범위인 3~20을 지원한다.
- `FR-SET-04`: 기본값은 쉬움, 병 높이 4, 색상 수 3이다.
- `FR-SET-05`: 난이도는 색상 가시성만 결정하며 퍼즐 크기와 독립적이다.

### 5.2 이동 규칙

- `FR-MOVE-01`: 비어 있지 않은 병만 출발 병으로 선택할 수 있다.
- `FR-MOVE-02`: 출발 병 맨 위에 연속된 같은 색 액체만 한 번에 이동할 수 있다.
- `FR-MOVE-03`: 목적지 병이 비어 있거나 목적지 맨 위 색이 이동 색과 같을 때만 이동할 수 있다.
- `FR-MOVE-04`: 실제 이동량은 연속 액체 수와 목적지의 남은 용량 중 작은 값이다.
- `FR-MOVE-05`: 같은 병으로 이동하거나 완성된 병을 출발 병으로 선택하면 상태를 변경하지 않는다.
- `FR-MOVE-06`: 생성기와 솔버는 화면과 동일한 이동 판정 함수를 사용한다.

### 5.3 역방향 퍼즐 생성

- `FR-GEN-01`: 생성기는 색상별로 가득 찬 완성 상태와 빈 병 2개로 시작한다.
- `FR-GEN-02`: 기존 `mixingSteps` 설정만큼 역이동을 적용해 초기 퍼즐을 만든다.
- `FR-GEN-03`: 각 역이동은 결과 상태에서 이전 상태로 돌아가는 정방향 이동이 실제 게임 규칙상 유효해야 한다.
- `FR-GEN-04`: 생성 과정의 정방향 복원 이동을 역순으로 기록해 보장된 풀이 경로를 만든다.
- `FR-GEN-05`: 즉시 직전 상태로 되돌아가는 이동과 이미 방문한 상태는 제외해 불필요한 순환을 줄인다.
- `FR-GEN-06`: 완성 상태이거나 혼합되지 않은 결과는 퍼즐로 채택하지 않는다.
- `FR-GEN-07`: 생성 시도는 기존 최대값인 10회로 제한하며, 모두 실패하면 무한 반복하지 않고 명시적인 생성 오류를 반환한다.
- `FR-GEN-08`: 반환 전에 기록된 풀이 경로를 재생해 병 용량, 색상 수량과 완료 상태를 검증한다.

### 5.4 난이도별 색상 공개

- `FR-DIFF-01`: 쉬움은 모든 색상을 표시한다.
- `FR-DIFF-02`: 보통은 각 병의 상단을 표시하고 나머지 위치의 50%를 게임 시작 시 한 번 결정해 표시한다.
- `FR-DIFF-03`: 어려움은 각 병의 현재 상단과 이동으로 공개된 위치만 표시한다.
- `FR-DIFF-04`: 보통 난이도의 최초 랜덤 가시성과 공개된 위치를 모두 저장하고 이어하기에서 동일하게 복원한다.
- `FR-DIFF-05`: 새 게임을 시작하면 이전 게임의 공개 상태를 초기화한다.

### 5.5 다음 한 수 힌트

- `FR-HINT-01`: 힌트는 난이도와 관계없이 요청할 수 있으며, 현재 퍼즐의 색상 공개 상태에 따라 계산 방식을 선택한다.
- `FR-HINT-02`: 일부 액체 블록의 색상이 숨겨진 상태에서는 숨은 색상, A*와 생성 시 기록된 풀이 경로를 사용하지 않고 공개된 정보만으로 즉시 유효함을 판정할 수 있는 이동을 찾는다.
- `FR-HINT-03`: 부분 공개 상태의 후보는 상단 이동 색상이 공개된 출발 병에서 비어 있거나 같은 공개 상단 색상을 가진 목적지 병으로 이동하는 조합으로 한정한다. 출발 병에서 이동할 블록은 모두 공개되어 색상과 연속 여부를 확정할 수 있어야 한다.
- `FR-HINT-04`: 부분 공개 상태의 후보는 다음 점수의 합이 높은 순서로 선택한다.
  - 공개 정보만으로 목적지 병이 단일 색상 완성 상태가 되면 `+100`
  - 비어 있지 않은 같은 색 목적지 병으로 합치면 `+50`
  - 이동이 확정된 공개 연속 블록 하나당 `+5`
  - 빈 병을 목적지로 사용하면 `-20`
- `FR-HINT-05`: 완전히 공개된 완성 병을 흐트러뜨리는 이동은 부분 공개 후보에서 제외한다.
- `FR-HINT-06`: 후보 점수가 같으면 출발 병 인덱스가 작은 이동, 그다음 목적지 병 인덱스가 작은 이동을 선택해 결과를 결정적으로 만든다.
- `FR-HINT-07`: 공개 정보만으로 확실한 후보가 없으면 퍼즐을 변경하거나 숨은 색상을 공개하지 않고 “현재 공개된 정보로 추천할 수 있는 이동이 없습니다”라고 안내한다.
- `FR-HINT-08`: 현재 퍼즐에서 빈 위치를 제외한 모든 액체 블록의 `isVisible`이 `true`이면 현재 전체 퍼즐을 A*로 탐색한다.
- `FR-HINT-09`: A*는 현재 게임의 병 높이와 공통 이동 규칙을 사용하며 난이도와 관계없이 적용한다.
- `FR-HINT-10`: A* 계산은 Web Worker에서 실행해 화면 입력과 애니메이션을 차단하지 않는다.
- `FR-HINT-11`: A*의 기본 탐색 한도는 1초 또는 50,000개 상태 중 먼저 도달하는 값이다.
- `FR-HINT-12`: 사용자가 힌트를 다시 요청하거나 화면을 이탈하면 진행 중인 A* 탐색을 취소한다.
- `FR-HINT-13`: A*가 제한 안에 답을 찾지 못하면 퍼즐을 변경하지 않고 힌트를 찾지 못한 사유를 표시한다.
- `FR-HINT-14`: 힌트는 출발 병과 도착 병 한 쌍만 강조하며 이동을 자동 실행하거나 색상을 추가로 공개하지 않는다.

### 5.6 저장과 이어하기

- `FR-SAVE-01`: 새 게임 생성 직후와 유효한 이동 직후 게임 상태를 `localStorage`에 저장한다.
- `FR-SAVE-02`: 퍼즐, 병 높이, 색상 수, 난이도, 가시성 상태와 생성된 풀이 경로를 저장한다.
- `FR-SAVE-03`: 기존 저장 데이터에 새 필드가 없어도 게임을 불러올 수 있어야 한다.
- `FR-SAVE-04`: 저장 데이터의 구조가 잘못됐으면 안전하게 무시하고 기본 설정으로 복구한다.
- `FR-SAVE-05`: 게임 완료 시 현재 게임 저장 데이터를 삭제한다.
- `FR-SAVE-06`: 저장 실패가 게임 진행을 중단시키지는 않되 개발 환경에서는 진단 가능한 오류를 남긴다.

### 5.7 완료 처리

- `FR-END-01`: 빈 병을 제외한 모든 병이 정확히 병 높이만큼 채워지고 단일 색상일 때만 완료로 판정한다.
- `FR-END-02`: 완료 시 축하 모달에서 새 퍼즐 시작과 홈 이동을 제공한다.
- `FR-END-03`: 새 퍼즐 시작은 완료한 퍼즐이나 이어하기 시점의 퍼즐을 재사용하지 않고 새로운 퍼즐을 생성한다.

## 6. 데이터 및 인터페이스 요구사항

아래 계약은 구현 시 사용할 최소 형태다. 실제 모듈 위치는 FSD 규칙에 따라 정하되 외부에서는 각 슬라이스의 public API로만 접근한다.

```ts
interface GeneratedPuzzle {
  puzzle: Puzzle;
  solutionPath: SolutionStep[];
}

interface SolutionStep {
  stateHash: string;
  move: Move;
}

interface GameState {
  puzzle?: Puzzle;
  bottleHeight: number;
  numColors: number;
  difficulty: Difficulty;
  revealedPositions?: RevealedPositions;
  initialVisibility?: RevealedPositions;
  solutionPath?: SolutionStep[];
}

interface SolverLimits {
  timeoutMs: number;
  maxVisitedStates: number;
}

type HintResult =
  | { status: 'found'; move: Move; source: 'astar' | 'visible-heuristic' }
  | {
      status: 'unavailable';
      reason: 'no-visible-move' | 'timeout' | 'state-limit' | 'no-solution';
    };
```

- 퍼즐 상태 해시는 같은 퍼즐이 항상 같은 값을 생성하는 결정적 표현이어야 한다.
- Web Worker와 UI 사이에는 직렬화 가능한 데이터만 전달한다.
- 기존 `GameState`에 추가되는 필드는 선택값으로 두어 저장 데이터 하위 호환성을 유지한다.
- 생성 시 기록한 풀이 경로는 퍼즐의 풀이 가능성 검증에만 사용하고 힌트 계산에는 사용하지 않는다.

## 7. 비기능 요구사항

- `NFR-01`: 생성과 힌트 도중 사용자 인터페이스가 멈추지 않아야 한다.
- `NFR-02`: 힌트 계산 상태를 로딩 표시와 함께 전달하고 중복 요청을 방지한다.
- `NFR-03`: 모든 버튼은 키보드로 조작 가능하고 의미 있는 접근성 이름을 가져야 한다.
- `NFR-04`: 모바일 세로 화면을 우선 지원하고 색상 수가 많을 때 보드가 화면 밖으로 잘리지 않아야 한다.
- `NFR-05`: 프로덕션 코드에서 생성 시도, 병 상태와 솔버 과정을 무조건 콘솔에 출력하지 않는다.
- `NFR-06`: 생성기·이동기·솔버가 퍼즐 배열을 입력받아 직접 변경하지 않는다.

## 8. 예외 및 실패 처리

- 생성 제한에 도달하면 홈으로 복귀하거나 재시도할 수 있는 오류 UI를 표시한다.
- A* 시간 또는 상태 한도 초과는 게임 오류로 취급하지 않고 힌트 불가 상태로 처리한다.
- Worker 오류 또는 취소 시 현재 퍼즐을 유지한다.
- 저장 공간 부족, 접근 차단 또는 손상된 JSON은 새 게임 플레이를 막지 않는다.
- 지원 범위를 벗어난 병 높이와 색상 수는 생성 전에 검증하고 생성기를 실행하지 않는다.

## 9. 테스트 및 인수 기준

### 9.1 단위 테스트

- 출발·목적지·용량·연속 색상별 이동 성공 및 실패
- 가변 병 높이에서 완료 판정
- 역방향 이동마다 대응하는 정방향 복원 이동이 유효한지 검증
- 최소 설정과 최대 설정의 색상 개수 및 병 용량 보존
- 생성 경로 전체 재생 후 완료 상태 도달
- 생성 최대 시도 초과 시 유한한 실패 반환
- A* 성공, 시간 초과, 상태 한도 초과와 해답 없음
- 부분 공개 상태에서 숨은 색상만 변경해도 공개 정보가 같으면 동일한 힌트 반환
- 같은 색 병 결합, 단일 색상 병 완성, 빈 병 이동과 공개 연속 블록 수에 따른 후보 점수 계산
- 동일 점수 후보의 출발 병·목적지 병 인덱스 우선순위
- 완전히 공개된 완성 병을 출발 병으로 사용하는 후보 제외
- 공개 정보로 확실한 이동이 없을 때 `no-visible-move` 반환
- 난이도와 관계없이 전체 공개 상태에서는 A*, 부분 공개 상태에서는 공개 정보 휴리스틱만 호출
- 난이도별 가시성 계산과 저장 후 복원
- 기존·손상된 저장 데이터 처리

### 9.2 통합 시나리오

- 새 게임 생성 → 여러 번 이동 → 홈 → 이어하기 → 동일 상태 복원
- 부분 공개 게임에서 힌트 요청 → 공개 정보 기반 병 강조 → 사용자가 직접 이동
- 부분 공개 게임에서 확실한 후보 없음 → 공개 정보 부족 안내 → 퍼즐과 공개 상태 유지
- 전체 공개 게임에서 힌트 요청 → A*가 계산한 병 강조 → 사용자가 직접 이동
- A* 제한 초과 → 원인에 맞는 힌트 불가 메시지 → 생성 경로로 폴백하지 않음
- 완료 → 저장 삭제 → 새 퍼즐 시작

### 9.3 출시 게이트

```bash
yarn build
yarn lint
yarn lint:fsd
yarn format:check
yarn test
```

모든 명령이 성공해야 출시할 수 있다. 현재 테스트 도구가 없으므로 구현 단계에서 Vitest를 추가한다.

## 10. 범위 제외 및 후속 검토

1차 출시에는 다음을 포함하지 않는다.

- 전체 정답 자동 재생
- 점수, 랭킹과 사용자 계정
- 서버 저장 및 여러 기기 동기화
- 멀티플레이
- 효과음과 배경음악
- 다크 모드

출시 후 실제 생성 시간과 힌트 성공률을 측정해 `mixingSteps`, 1초 제한과 50,000개 상태 한도를 조정한다. 분석 백엔드가 도입되기 전에는 개발 성능 테스트와 QA 기록을 기준으로 조정한다.
